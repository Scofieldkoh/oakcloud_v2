## Frozen shared decisions

### C01 — canonical editor authority

CORE owns the editor session and the only local `EditorRevision` authority. A session snapshot contains `sessionKey`, local revision, canonical HTML content, `contentJson`, and lossless field definitions when applicable. Pagination/projection never increments canonical revision.

`CanonicalInputBridge` remains the revision/stale-projection boundary. SEMANTICS position maps copy the session/revision supplied by CORE; they do not allocate another revision counter.

### C02 — structural positions and transactions

Frozen position shape:

```ts
type A4Position =
  | { kind: 'text'; nodeId: string; offset: number; affinity: 'before' | 'after' }
  | { kind: 'children'; nodeId: string; index: number; affinity: 'before' | 'after' };

interface A4Selection {
  anchor: A4Position;
  focus: A4Position;
}

interface CanonicalEditorDocument {
  readonly internalHtml: string;
}

type A4TransactionResult =
  | {
      status: 'applied';
      document: CanonicalEditorDocument;
      selection: A4Selection;
      changedNodeIds: readonly string[];
    }
  | { status: 'unchanged'; reason: string }
  | { status: 'rejected'; code: string; message: string };
```

Collapsed structural selections must round-trip as one logical caret. Affinity distinguishes zero-text structural boundaries such as `<br>`, fields/atomics, empty blocks/cells, and semantic page breaks. Invalid or stale positions return typed rejection/mapping behavior; they do not fall back to a physical page end.

### C03 — manual break representation

Frozen v2 nested marker:

```html
<span data-a4-break="page"></span>
```

Example inside a numbered item:

```html
<ol start="5"><li><p>Before<span data-a4-break="page"></span>After</p></li></ol>
```

This remains one canonical OL/LI/P item. Projection may clone ancestry and add runtime continuation metadata, but persisted content must not contain `data-flow-*` or `--flow-list-start` measurement state.

Legacy top-level hard break remains readable:

```html
<div class="page-break" data-break-type="hard"></div>
```

Feature detection must inspect markup as well as optional metadata because TemplatePartial does not depend on `contentJson` for break semantics. Arbitrary page breaks inside table cells remain unsupported unless a later tested table-row/cell contract is explicitly added.

### C04 — projection mapping and native input

Frozen projection mapping associates every map with CORE's immutable source identity:

```ts
interface A4ProjectionPositionMap {
  sessionKey: EditorSessionKey;
  documentRevision: EditorRevision;
  fragments: readonly {
    fragmentIndex: number;
    sourceRanges: readonly {
      sourceNodeId: string;
      startTextOffset: number;
      endTextOffset: number;
    }[];
  }[];
}
```

Rendered native input is accepted only against a current/reconcilable projection. Stale physical DOM never replaces newer canonical content. Composition remains a bounded native-edit session and cannot be acknowledged as a complete save while unreconciled.

### C05 — field identity, grammar and lifecycle

Field identity is stable and scoped by owner stable ID plus persisted field ID when present, otherwise the scoped stored key. Display labels or partial display names never define identity, and collision handling must not invent underscore aliases that leave references unbound.

The lossless stored-definition boundary preserves:

- `id` when present;
- key/label/type/source/category/path;
- explicit versus omitted `required`;
- default/format/options;
- `linkedTo` and `sourcePartial`;
- all supported legacy types, including `list` and `conditional`;
- arbitrary JSON-compatible forward metadata.

Unsupported legacy types are preserve-only until intentional conversion. Typed values distinguish missing, empty, false, zero, text/date/numeric/currency semantics and legacy structured values.

F1 may implement the single HTML-aware parser after dispatch, but the grammar direction frozen at G0 includes supported simple/spaced references, modifiers, each/if/unless/with blocks, loop variables, partials, current `data-template-each` constructs, service-context references, and explicit diagnostics for malformed/unknown/missing/circular cases.

### C06 — content policy and HTML trust

Ordinary declarative field values have no trusted-HTML authority. Stored/client/pasted/token `renderMode` metadata cannot mint trusted rich content.

Trusted rich output requires a canonical in-process origin capability representing one of:

- template partial;
- canonical builder;
- service composition.

Ordinary text escaping remains a later F2/W integration behavior and was not activated in Wave 0. Existing raw interpolation is captured as a known baseline defect.

The shared semantic content policy must preserve supported authored structures such as blockquote, caption/tfoot, list start, safe table semantics, sup/sub and the C03 break attribute while excluding projection-only flow metadata and executable/unsafe markup.

### C07 — persistence concurrency

Frozen public mutation precondition:

```ts
expectedRevision
```

Revision mapping:

| Resource | Internal revision source |
| --- | --- |
| DocumentTemplate | existing `version` |
| TemplatePartial | existing `version` |
| GeneratedDocument | dedicated future `revision Int @default(0)` |
| generation batch/session | existing batch revision |

`updatedAt` is not the canonical concurrency token. `GeneratedDocument.templateVersion` remains generation provenance and must not be reused as edit revision.

Successful mutation responses add an acknowledged public `revision`. A stale writer returns HTTP 409 with stable `VERSION_CONFLICT` semantics. During transition, `expectedRevision` may remain optional only while capability data says so; once strict mode is enabled, missing preconditions receive a recoverable required-precondition response rather than an unchecked write.

Writes must atomically scope by ID, tenant, deleted/editable state and expected revision where applicable, then increment the revision in that same accepted mutation. No stale-write fallback is permitted.

### C08 — metadata, drafts and preview identity

All editor/output-affecting metadata must be saved from the same canonical snapshot. Layout changes use the shared merge helper and preserve unrelated `contentJson` keys. Content-only edits cannot use `null` as an implicit metadata reset.

Draft metadata will bind base server revision, session identity and local snapshot revision. A successful canonical save may only clear drafts covered by that acknowledged snapshot; newer/other-user drafts remain intact.

Preview results are bound to the current session/snapshot/context identity and stale responses are ignored.

### C09 — output compatibility

All readers/output paths must become compatible before v2 writers are enabled. This includes editor reopen, partials, preview, batch, local print, HTML/PDF export, server/static pagination consumers and generated bundle compatibility.

Output failure must not return clipped fixed-height content as successful PDF output. Font readiness/cleanup and actual output parity remain later execution gates.

Wave-0 synthetic output fixtures capture required structures including heading, ordered list starting at 5, nested list, blockquote, table caption/footer, fields, exact C03 nested break, legacy hard break and first/last sentinels. Actual Puppeteer PDF-byte/page-image verification remains an explicitly open later integration check.

### C10 — deployment capability contract

Frozen capability shape:

```ts
type RevisionPreconditionMode = 'optional' | 'required';

interface A4EditorCapabilities {
  readerFormatLevel: 1 | 2;
  allowedWriterFormatLevel: 1 | 2;
  revisionPrecondition: RevisionPreconditionMode;
}
```

No existing generic A4 capability endpoint was found. The frozen W0 design is to use one server-owned module and an authenticated page-bootstrap producer following the existing `src/app/api/page-bootstrap/*/route.ts` pattern:

- proposed module: `src/lib/document-editor/a4-editor-capabilities.ts`;
- proposed route: `src/app/api/page-bootstrap/document-editor/route.ts`;
- browser fallback when absent: `{ readerFormatLevel: 1, allowedWriterFormatLevel: 1, revisionPrecondition: 'optional' }`.

Server-side consumers use the same capability module directly; client claims never raise server writer authority.

Reader level must be raised before writer level. Rollback lowers writer level first, relaxes strict revision enforcement before rolling back clients, and never lowers reader capability below formats that may already exist in stored content.
